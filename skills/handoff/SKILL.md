# 会话交接

用户准备结束当前会话。目标：生成一份交接摘要，让下一个全新会话能无缝接续。

## Steps

### 1. 盘点本次变更

- `git status` 查看未提交的改动。
- `git log --oneline -20` 查看近期提交（聚焦本次会话的）。
- 回顾本次会话讨论和操作的内容。
- 记录关键决策、用户纠正、未解决的问题。

### 2. 判断是否中途交接

用户是在一个自然边界结束，还是被迫中断？

中途信号：
- 有未提交的半成品代码
- 最后几轮在调试或实现尚未完成的功能
- 用户说了"先停"、"得走了"、或者 context 告警触发了

### 3. 生成交接摘要

用会话所用的语言撰写，包含以下部分：

```
## 交接摘要

### 本次完成
- （1-3 句话概述完成了什么）

### 改动的文件
- 文件路径 — 简要说明

### 关键决策
- 做了什么选择、为什么

### 当前状态
- 什么能用了、什么还不行

### 下一步
- 具体可执行的待办事项

### WIP（如有）
- 正在进行什么、试过什么、下一步该做什么
```

简洁为上，交接摘要应该是可扫读的，不是面面俱到的报告。

### 4. 复制到剪贴板

用 `pbcopy`（macOS）或 `xclip -selection clipboard`（Linux）将交接摘要复制到剪贴板，告知用户已复制。

### 5. 确认

输出简短总结，然后说：「可以开新对话了，粘贴交接内容即可继续。」

## 跳过的情况

- 用户说"不用交接"、"直接退"
- 本次无实质改动、无重要讨论 — 直接说「本次无实质改动，可以直接开新对话。」
